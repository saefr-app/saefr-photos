## Milestone assessment

M11B adds nullable `asset.owner_id`, the approved validated FK, ordering index and enforced `NOT VALID` ownership check. Historical NULL-owned rows remain unchanged and cannot be retrieved through the application. M11C requires an authenticated actor for every new insert, uses owner predicates in every repository read, opens storage only after a scoped lookup, and finalizes uploads after processing under a short user-then-session transaction. M11D mounts the scoped module together with an early Fastify `onRequest` authentication/Origin/CSRF gate and exact M11 startup-readiness check. Administrators have no cross-owner media privilege. Optional M11E legacy mapping is deferred; no owner was inferred or assigned.

## Limits and remaining gates

- **No real-data upgrade or restore rehearsal.** The development PostgreSQL database, its Docker volume, original photographs and thumbnails were not accessed or modified. A real upgrade requires a matching database/media backup, tested recovery, isolated rehearsal, compatibility review and separate maintainer approval. Old M10 binaries reject the M11 schema. The unvalidated ownership check complicates restoring legacy NULL rows into an already-M11 catalog.
- **Legacy assets remain quarantined.** Optional 11E provenance-based mapping was not implemented; no first-admin backfill or inference is authorized. Disabled users retain ownership. New owned galleries can be used only after an approved deployment path.
- **No complete filesystem/database atomicity or crash recovery.** Uncertain COMMIT retains possible orphans; interruption can strand temporary/published files. Comprehensive filesystem write/cleanup fault injection, safe reconciliation, fsync/NAS behavior and privileged directory races remain open. No broad automatic cleanup was added.
- **Authorization is request-time for reads.** An in-flight stream can finish after revocation. Uploads have separate locked final revalidation. Listing remains unpaginated and no deletion/sharing/transfer/mobile credentials or worker is implemented.
- **Deployment validation remains outstanding.** No production TLS/reverse-proxy/cookie test, publicly exposed API, Dockerized backend or real backup restoration was performed. The local suite is not proof of deployment readiness. No GitHub CI workflow result was verified or claimed.
- **Review and Git gates remain.** Independent GPT-6 Astra Extra High security review returned **PASS** with no confirmed checkpoint blocker, and the maintainer approved the M11F documentation checkpoint. A PR into `integration` and any merge need subsequent separate authorization. Deployment and real-data migration remain unapproved; `main` is reserved for a validated self-hostable alpha.
