## Technical decisions

The runner uses `docker run` rather than Testcontainers or the root Compose project. This requires no new npm dependency and cannot select the development Compose volume by default. Each run creates a random container and database name, a random password, an ephemeral `--tmpfs /var/lib/postgresql`, `--rm`, and a random port published only on `127.0.0.1`. Docker inspection verifies the image, label, test credentials, auto-remove flag, tmpfs, lack of non-tmpfs mounts and port binding. The test repeats these checks before it creates the `asset` table or deletes fixtures. The test creates `ConfigService` directly; it never loads `.env`, and its internal test values take precedence over inherited `POSTGRES_*` values. Cleanup looks up the random name, verifies ownership again, then stops that exact container ID; this also covers a failure after Docker created the container but before returning its ID. Docker command errors are printed without their command arguments so the temporary password is not logged.

The test schema is the DDL generated by `server/app/models/asset.py` using the installed `sqlmodel==0.0.47` and PostgreSQL dialect: `id UUID PRIMARY KEY`, `size INTEGER`, `created_at TIMESTAMP WITH TIME ZONE`, and non-null varying-character fields for filename, MIME type and storage path. This reproduces the legacy model definition, not a verified dump of the persisted table. Schema creation is test-only; no production migration was added.

The suite tests `AssetsRepository.create`, `findById`, `findFileById`, `findAll` timestamp and UUID tie ordering, missing records, UUID round-trip, UTC timestamp handling, the maximum signed 32-bit size and out-of-range rejection. The timestamp test inserts an offset timestamp through PostgreSQL and reads it through the real repository, so the database conversion is exercised. It also exercises `AssetsService` public metadata serialization with the real repository and `HealthService` success/failure using real PostgreSQL connections. The service serialization check does not exercise HTTP routing or filesystem I/O; the existing HTTP E2E tests cover HTTP with mocks.

## Final self-review

- **Fixed, medium:** A Docker CLI failure could have printed the temporary test password as part of the command text. The runner now suppresses command arguments in Docker error messages.
- **Fixed, medium:** Cleanup previously depended on `docker run` returning a container ID. It now re-inspects the random name and checks image, label, credentials, temporary storage and ID before stopping anything.
- **Fixed, low:** A handled signal could have produced a successful exit status. `SIGINT`, `SIGTERM` and `SIGHUP` now mark the run failed and ask the test child to stop; an unresponsive child is force-killed after five seconds.
- **Fixed, low:** The first timestamp test converted an offset to a JavaScript `Date` before inserting it. The revised test passes an offset timestamp to PostgreSQL and reads it through Kysely.
- **No production-code changes:** The code changes are confined to the test runner, integration spec, Vitest config and npm script. The remaining changes are documentation.

## Findings and remaining risks

- **Confirmed:** The pinned SQLModel definition generates a PostgreSQL `UUID` primary key, `INTEGER` size and time-zone-aware timestamp. PostgreSQL 18 and `pg` return `created_at` as a JavaScript `Date`; the service emits UTC ISO text. A size of `2,147,483,647` works, while `2,147,483,648` is rejected by the integer column.
- **Unverified:** The persisted development `asset` table may differ from the current Python model. Its container was stopped, and this milestone deliberately did not start or query it. The real column types, constraints, indexes and historical timestamp values need a read-only comparison when the maintainer makes that database available.
- **Known limitation (medium):** An uncatchable runner termination (for example, `SIGKILL` or host crash) can leave the tmpfs-backed test container running. One abrupt interactive PTY Ctrl-C during review did so; its identity was verified and it was manually stopped. Direct `SIGINT`, `SIGTERM` and `SIGHUP` to the runner cleaned up correctly. The random database remains separate from the development volume. Inspect the label and container identity before stopping a leftover test container manually.
- **Follow-up:** Use the actual persisted schema findings to plan backwards-compatible migrations in M8 only after M7 review and approval. The current upload cap is 20 MiB, below the integer boundary, but larger future assets will require a planned schema change.
